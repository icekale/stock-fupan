# 强势股规则选股 V1 设计

日期：2026-06-11
状态：已确认设计，待用户审阅

## 目标

把用户给出的 8 条强势股、趋势、低吸和空仓纪律落到程序里，做成后台可手动运行的选股模块。

第一版输出的是“复盘研究与盘中观察清单”，不是自动交易系统。程序应基于已接入或已在项目中规划的行情数据源，筛出近 20 日出现过涨停的股票，并解释为什么进入关注、等待回踩、提示减仓风险或建议空仓。

## 已确认决策

- 产品入口放在 Web 后台首页，作为独立的“强势股规则选股”卡片。
- 第一版手动运行，不做自动买卖，也不自动定时盘中盯盘。
- 盘中纪律先输出为观察提示，只有在后续接入稳定分时运行能力后再做实时监控。
- 不改现有日报主流程；后续可把筛选结果接入日报，但不作为 V1 必须项。
- 不覆盖当前工作树里已有的 a-stock-data 接口版本更新改动。

## 范围

### 包含

1. 后端新增强势股规则筛选服务。
2. 后端新增手动运行 API。
3. 前端新增后台操作卡片和结果列表。
4. 规则结果包含评分、状态、命中原因、风险原因和盘中观察提示。
5. 单元测试覆盖核心规则分支。
6. API 与前端测试覆盖手动运行、结果渲染和错误展示。

### 不包含

- 不做自动下单。
- 不做账户、仓位或真实持仓同步。
- 不做 9:30-10:00 的实时推送和轮询监控。
- 不做全市场无节流批量抓取。
- 不引入机器学习、回测系统或复杂策略 DSL。
- 不承诺在候选池数据源缺失时仍然给出完整全市场筛选。

## 数据源设计

### 候选池

硬规则是“只选 20 日内有过涨停的股票”。第一版候选池必须来自能表达该条件的数据源。

优先级：

1. THSDK 问财能力：查询“20日内有过涨停，非 ST，A股”，返回股票代码、名称、最近涨停信息、连板或断板描述。
2. 若后续启用 iwencai 官方 API，可作为同等候选池来源。
3. 若候选池数据源不可用，API 返回明确错误，不使用“今日热点”“当日涨停复盘”冒充 20 日全市场候选池。

这条边界是为了避免筛选结果看起来完整、实际漏掉大量股票。

### K 线与均线

每个候选股需要最近至少 220 个交易日的日 K 数据。第一版封装一个轻量 K 线客户端：

- 首选 a-stock-data 参考中的百度股市通 K 线接口，因其自带 MA5、MA10、MA20。
- 若 MA 字段缺失，本地用 close 计算 MA5、MA10、MA20。
- 200 日新高使用最近 200 根 K 线的最高价判断。
- 若单只股票 K 线不足，保留该候选但标记为 `data_incomplete`，不进入最高等级。

### 盘中数据

V1 不依赖分时数据完成筛选。规则 6 和 7 中的盘中动作只转成观察提示：

- 买绿不买红、卖红不卖绿。
- 高开 7% 以上，10 点前封不住板，减仓锁定利润。
- 早盘大跌回踩 MA10/MA20 或快速站稳日内均线，可以观察低吸机会。

后续若接入稳定分时数据，再把这些提示升级为实时信号。

## 规则模型

每只股票输出：

```text
symbol
name
trade_date
status
score
rule_hits
risk_flags
intraday_notes
metrics
data_status
```

`status` 取值：

- `focus`：可关注。
- `wait_pullback`：等回踩。
- `reduce_risk`：减仓风险。
- `empty`：空仓。
- `data_incomplete`：数据不足。

### 规则 1：20 日涨停

这是硬过滤。候选池必须证明 20 日内出现过涨停或接近涨停。

判定：

- 主板、科创板、创业板和北交所不在 V1 内细分涨跌停制度，只使用候选池来源的“涨停”语义作为硬过滤依据。
- K 线复核时，若最近 20 日最大涨幅接近涨停，作为增强证据，但不替代候选池。

### 规则 2：红肥绿瘦与量能

用近 20 日 K 线计算：

- 阳线实体均值：`close > open` 时的 `close - open`。
- 阴线实体均值：`open > close` 时的 `open - close`。
- 上涨日成交量均值。
- 下跌日成交量均值。

加分条件：

- 阳线实体均值大于阴线实体均值。
- 上涨日成交量均值大于下跌日成交量均值。
- 最近一次上涨日实体较饱满，并伴随放量。

风险条件：

- 下跌日放量明显大于上涨日。
- 大阴线实体扩大。

### 规则 3：MA5、200 日新高、放量上涨和放量滞涨

加分条件：

- 最新收盘价在 MA5 上方。
- 最新高点或收盘价创 200 日新高。
- 最近一日涨幅为正，成交量高于 5 日均量。

减仓风险：

- 成交量高于 5 日均量，但涨幅很小或上影线较长，标记为放量滞涨。
- 创新高后次日不能继续站稳 MA5，降级为等待或减仓风险。

### 规则 4：不冲高不卖、不跳水不买、趋势不明不交易

V1 不在盘中直接买卖，只转成状态约束：

- 趋势清晰向上时才允许 `focus`。
- 趋势横盘或均线缠绕时输出 `wait_pullback`。
- 跌破关键均线或出现跳水式阴线时输出 `empty`。

### 规则 5：趋势第一

趋势强弱是最终状态的第一优先级。

加分条件：

- 最新收盘价高于 MA5、MA10、MA20。
- MA5 高于 MA10，MA10 高于 MA20。
- 回调幅度小于前一轮上涨幅度，且未破 MA10。

空仓或降级：

- 阴跌后横盘不视为抄底。
- 跌得多但反弹弱，输出 `empty` 或 `wait_pullback`。
- 只要趋势证据不足，不能因为短线涨幅高就输出最高状态。

### 规则 6：买绿不买红、卖红不卖绿

V1 输出观察提示，不参与评分：

- 对 `focus` 股票提示“买点优先看分歧回落承接，不追红盘急拉”。
- 对 `reduce_risk` 股票提示“冲高反弹优先兑现，不在绿盘恐慌卖出”。

### 规则 7：早盘加减仓纪律

V1 输出观察提示，不做实时触发：

- 高开 7% 以上，10 点前封不住板：提示减仓风险。
- 早盘大跌回踩 MA10/MA20 后快速站稳：提示低吸观察。
- 早盘大涨：提示降低追高优先级。

### 规则 8：空仓纪律

任一硬空仓条件触发时，最终状态直接降为 `empty`：

- MA5 拐头向下。
- 最新 K 线跌在 MA5 或 MA10 下方。
- 出现实体阴线，且连板断板或强势修复证据不足。

若触发其中两项以上，输出高优先级风险说明。

## 评分与状态

基础分 0 到 100，只用于排序，不替代状态规则。

建议权重：

- 20 日涨停候选资格：硬过滤，不计分。
- 红肥绿瘦与量能：25 分。
- MA5 与均线趋势：25 分。
- 200 日新高与强势突破：20 分。
- 放量上涨质量：15 分。
- 风险扣分：最多扣 30 分。
- 数据完整性扣分：最多扣 20 分。

状态决策：

```text
硬空仓条件 -> empty
放量滞涨或高位转弱 -> reduce_risk
趋势上行但买点不佳 -> wait_pullback
趋势上行、量价健康、风险较低 -> focus
关键数据缺失 -> data_incomplete
```

## 后端 API

新增 `POST /api/strong-stocks/screen`。

请求：

```json
{
  "trade_date": "2026-06-11",
  "limit": 30
}
```

返回：

```json
{
  "trade_date": "2026-06-11",
  "source_status": [
    {
      "source": "THSDK 问财",
      "status": "success",
      "detail": "返回 87 只 20 日涨停候选"
    }
  ],
  "items": [
    {
      "symbol": "603890.SH",
      "name": "春秋电子",
      "status": "focus",
      "score": 82,
      "rule_hits": ["20日内涨停", "收盘价在MA5上方", "阳线实体强于阴线", "放量上涨"],
      "risk_flags": [],
      "intraday_notes": ["买点优先看分歧回落承接，不追红盘急拉"],
      "metrics": {
        "close": 12.34,
        "ma5": 11.80,
        "ma10": 11.20,
        "ma20": 10.80,
        "volume_ratio_5d": 1.42,
        "is_200d_high": true
      },
      "data_status": "complete"
    }
  ],
  "generated_at": "2026-06-11T19:30:00+08:00"
}
```

错误：

- 候选池不可用：`503`，说明需要启用 THSDK 或后续 iwencai API。
- K 线源部分失败：`200` 返回可用股票，同时在 `source_status` 里列出失败数量。
- 参数非法：`422`。

## 后端组件

新增文件建议：

- `apps/api/app/services/strong_stock_screening.py`
- `apps/api/tests/test_strong_stock_screening.py`
- `apps/api/tests/test_strong_stock_screening_api.py`

核心边界：

- `StrongStockCandidateProvider`：负责返回 20 日涨停候选池。
- `StrongStockKlineProvider`：负责返回单只股票 K 线。
- `StrongStockScreeningService`：只做规则计算和结果排序。

规则计算应是纯函数优先，方便单测用固定 K 线验证。

## 前端设计

在后台首页新增“强势股规则选股”卡片：

- 日期输入沿用现有交易日默认逻辑。
- 按钮：`运行筛选`。
- 状态摘要：候选数量、可关注数量、减仓风险数量、空仓数量。
- 结果列表显示股票、状态、评分、关键理由和风险。
- 错误区域显示数据源不可用或部分失败原因。

界面保持当前后台工具风格，不做单独落地页。

## 测试

后端单测：

- 20 日内无涨停的股票不进入结果。
- 红肥绿瘦、上涨放量提高分数。
- 收盘价在 MA5 上方和 200 日新高提高分数。
- 放量滞涨输出 `reduce_risk`。
- MA5 下拐、跌破均线、实体阴线断板未修复输出 `empty`。
- K 线不足输出 `data_incomplete`。
- 候选池不可用返回明确错误。

API 测试：

- `POST /api/strong-stocks/screen` 返回结构化结果。
- 候选池异常时返回 503。
- `limit` 参数限制输出数量。

前端测试：

- 渲染选股卡片。
- 点击运行后展示结果。
- 展示 source status 和错误信息。
- 不影响现有数据源状态、报告生成和自选股导入功能。
