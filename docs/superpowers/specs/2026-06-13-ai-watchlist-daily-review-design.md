# AI 自选股每日复盘系统设计

## 背景

当前系统已经具备日报生成、定时任务、自选股导入、自选股观察、风险检测、TickFlow/a-stock-data 数据源等基础能力。用户的真实痛点不是缺少一个更长的自选股列表，而是：

- 自选股越来越多，几天后容易忘记当初为什么关注。
- 某个板块开始走强时，不能及时知道自己的自选股是否在同一方向。
- 涨停股、板块强度、资金流向和自选股之间缺少每日自动关联。
- 风险信号需要每天检查，而不是只在用户手动打开软件时才发现。

本次设计目标是新增一个独立的“AI 自选股每日复盘系统”。它和日报功能共用行情、板块、新闻、风险检测和调度基础设施，但业务入口、数据模型、复盘结果和通知逻辑保持独立。

## 目标

第一版要做到：

- 建立长期维护的自选股池，支持分组、标签、关注理由和 AI 记忆。
- 每天定时复盘自选股，生成结构化结果。
- 计算自选股所属板块的涨跌、强度、资金流入流出和涨停联动。
- 判断自选股是否触发趋势风险、负面新闻风险、严重异动警告。
- 把每日重要变化通过企业微信、飞书、Telegram、邮件发送给用户。
- 在系统内保留历史复盘记录，方便回看“当时为什么关注”和“后来发生了什么”。

不做：

- 不做自动交易。
- 不把提醒写成买卖指令。
- 不做盘中监控第一版；盘中功能后续独立设计。
- 不替代现有日报，而是增加一个专门面向自选股的复盘模块。

## 推荐方案

采用独立“自选股复盘中枢”方案。

复盘中枢包括五层：

1. 自选股知识库：维护股票、分组、标签、关注理由、状态和 AI 记忆。
2. 每日复盘任务：每天收盘后计算自选股和板块状态。
3. 板块联动模型：判断自选股和当日强势板块、涨停股之间的关系。
4. AI 摘要与记忆：把每日观察沉淀为可追踪的结构化结论。
5. 通知发送层：统一生成消息，再分发到企业微信、飞书、Telegram、邮件。

这个方案比把功能继续塞进日报更清晰，也比写独立脚本更容易维护和回溯。

## 复盘数据源

优先级：

1. TickFlow：优先用于自选股行情、日 K、分钟线权限后续用于盘中、行业/主题行情能力可用时优先使用。
2. a-stock-data：用于补齐行业、题材、资金、公告、新闻、板块归属等数据。
3. 东方财富/其他现有源：仅用于 TickFlow 或 a-stock-data 无法覆盖的独有字段。

第一版需要的数据：

- 自选股实时或收盘行情。
- 自选股日 K，至少包含 MA5/MA10/MA20、成交量、成交额。
- 个股所属行业和概念。
- 行业/概念涨跌幅。
- 行业/概念资金流入流出。
- 当日涨停股和涨停股所属板块。
- 负面新闻、公告、严重异动风险标记。

## 每日复盘流程

每日收盘后执行一次，默认时间建议 19:30，避免收盘后数据源未完全更新。

流程：

1. 读取自选股池，默认范围是 `自选` 分组，也支持以后选择具体分组。
2. 拉取自选股行情、K 线、行业、概念、资金流。
3. 拉取当日涨停池和强势板块。
4. 计算每只自选股的趋势状态：
   - 是否站上 MA5。
   - MA5 是否拐头向下。
   - 是否跌破 MA10/MA20。
   - 是否接近或突破 200 日新高。
   - 是否放量上涨、放量滞涨、缩量回调。
5. 计算板块联动：
   - 自选股所属板块当日涨幅。
   - 板块资金流入流出。
   - 板块涨停数量。
   - 自选股是否和当日涨停股同题材。
6. 计算风险：
   - 负面新闻。
   - 严重异动警告。
   - 实体阴线。
   - 跌破关键均线。
   - 连板断板后未修复。
   - 放量滞涨。
7. 生成 AI 摘要和单股观察。
8. 保存复盘结果。
9. 发送通知。

## 板块联动模型

每只自选股生成一个关注优先级。

### 个股趋势分

加分项：

- 股价在 MA5 上方。
- MA5/MA10/MA20 多头排列。
- 近期接近或突破 200 日新高。
- 放量上涨且价格有推进。
- 回调幅度小、趋势仍保持。

扣分项：

- MA5 拐头向下。
- K 线跌在均线下方。
- 出现实体阴线。
- 放量滞涨。
- 连板断板后未修复。

### 板块强度分

加分项：

- 所属板块涨幅靠前。
- 所属板块有多只涨停。
- 所属板块资金净流入。
- 自选股所在分组与当日强势主题高度重合。

扣分项：

- 板块退潮。
- 板块资金净流出。
- 板块涨停数量减少且高位股亏钱效应扩大。

### 涨停联动分

重点判断：

- 今日涨停股是否和自选股同板块。
- 同板块涨停数量是否增加。
- 涨停股中是否出现自选股的上下游、同题材或同概念标的。
- 自选股是否是板块内未启动、刚启动或已高位。

### 风险扣分

风险项不被强势板块覆盖。即使板块很强，如果个股触发严重风险，也要在结果里醒目标注。

风险包含：

- 负面新闻。
- 严重异动警告。
- 放量滞涨。
- 跌破关键均线。
- 实体阴线。
- 高位长上影。
- 高开 7% 以上但 10 点前无法封板，后续盘中版本使用。

## 结果分层

每日复盘结果按优先级分成四类：

- `重点提醒`：自选股或所属板块开始明显变强，需要当天复盘。
- `继续观察`：趋势未坏，但没有足够触发条件。
- `风险检查`：有负面新闻、严重异动、趋势破位或放量滞涨。
- `暂时降级`：板块弱、个股弱、趋势不明朗，提醒减少关注频率。

文案保持研究和提醒口径，不输出“买入/卖出”命令。

## AI 记忆规则

AI 每天为重点股票写一条简短观察，落入 `watchlist_stock_notes`。

单条观察包含：

- 当天发生了什么。
- 和原始关注理由是否相关。
- 所属板块是否变强。
- 资金和量价是否确认。
- 明天应该观察什么条件。
- 是否需要降级或风险检查。

示例：

`2026-06-13：MLCC 方向出现 3 只涨停，风华高科涨幅靠前但未突破前高，成交额放大。当前更像板块开始升温后的观察点，明日重点看是否站稳 MA5 且板块涨停数量继续扩散。`

## 通知设计

第一版直接支持：

- 企业微信机器人。
- 飞书机器人。
- Telegram Bot。
- 邮件 SMTP。

采用统一通知接口：

`WatchlistReviewNotifier.send(review, channels)`

复盘服务只生成一份标准消息：

- 标题。
- 日期。
- 市场摘要。
- 重点提醒股票。
- 风险股票。
- 板块联动。
- 今日涨停与自选股关联。
- 链接到系统内复盘详情页。

各通道适配器负责格式转换：

- 企业微信：Markdown webhook。
- 飞书：富文本或 Markdown webhook。
- Telegram：HTML/Markdown 消息。
- 邮件：HTML 邮件。

发送策略：

- 一个通道失败不影响其他通道。
- 每个通道记录发送结果。
- 支持前端试发。
- 支持每日复盘完成后自动发送。
- 支持“只发重点提醒/风险提醒”阈值，避免每天噪音过多。

## 页面设计

新增一级页面：`自选股复盘`。

页面包含：

- 今日复盘摘要。
- 重点提醒。
- 风险检查。
- 板块联动。
- 涨停关联。
- 单股复盘表。
- AI 观察历史。
- 通知发送记录。

自选股管理页面负责维护池子；自选股复盘页面负责看每日结果。两者独立但互相跳转。

## API 设计

新增 API：

- `GET /api/watchlist-reviews/latest`
  - 返回最近一次自选股复盘。

- `GET /api/watchlist-reviews`
  - 分页返回历史复盘。

- `POST /api/watchlist-reviews/run`
  - 手动运行一次自选股复盘。

- `GET /api/watchlist-reviews/{review_id}`
  - 查看复盘详情。

- `GET /api/watchlist-review-schedule/status`
  - 查看复盘定时状态。

- `POST /api/watchlist-review-schedule/status`
  - 修改复盘定时开关、时间和时区。

- `GET /api/notification-channels`
  - 查看通道配置状态。

- `POST /api/notification-channels/{channel_id}/test`
  - 发送测试通知。

- `POST /api/watchlist-reviews/{review_id}/notify`
  - 对某次复盘重新发送通知。

## 调度设计

复用现有 API lifespan 后台循环模式，但新增独立服务：

- `watchlist_review_schedule.py`
- `run_due_watchlist_review_schedule(...)`

调度规则：

- 默认每天 19:30。
- 每个交易日最多自动生成一次。
- 如果当天已经有 `completed` 复盘，自动跳过。
- 失败后记录错误，下一次循环可重试。
- 手动运行不受自动调度限制，但要标记为手动触发。

## 错误处理

- 自选股池为空：生成空复盘，通知可跳过，并提示需要添加自选股。
- TickFlow 失败：允许 a-stock-data 补齐可用字段，结果中标记数据源降级。
- 板块资金数据缺失：不阻塞复盘，但在摘要中说明该字段不可用。
- 通知通道未配置：显示未配置，不发送。
- 单个通知通道失败：记录失败，其他通道继续发送。
- AI 摘要失败：保留规则计算结果，AI 评论字段显示生成失败原因。

## 测试计划

后端：

- 自选股池为空时能生成空复盘。
- 有自选股时能生成每日复盘和单股明细。
- 板块涨停与自选股同题材时，能产生联动提醒。
- 负面新闻和严重异动会进入风险检查。
- 自动调度每天只生成一次。
- 通知通道失败不影响复盘保存。
- 企业微信、飞书、Telegram、邮件适配器能格式化并发送测试消息。

前端：

- 自选股复盘页面展示最近复盘。
- 重点提醒、风险检查、板块联动分区清晰。
- 通知配置页展示四个通道的配置状态和试发入口。
- 手动运行复盘后有进度和结果反馈。

浏览器验证：

- 打开自选股复盘页面。
- 手动运行复盘。
- 查看今日摘要、单股明细和通知记录。
- 对至少一个通道执行试发。

## 分阶段交付

### 阶段 1：自选股池与分组基础

完成长期自选股池、分组、标签、多分组关系和删除分组不删除股票。

### 阶段 2：每日复盘数据结构与手动运行

新增复盘表、复盘服务和手动运行 API。先保存规则计算结果，不急于发送通知。

### 阶段 3：板块联动、涨停关联、风险检查

接入板块涨跌、资金流、涨停池、负面新闻、严重异动。形成 `重点提醒`、`继续观察`、`风险检查`、`暂时降级`。

### 阶段 4：AI 摘要与记忆

生成每日摘要和单股观察，写入股票记忆。

### 阶段 5：四通道通知

接入企业微信、飞书、Telegram、邮件。支持自动发送、手动重发、测试发送和发送记录。

### 阶段 6：独立 UI

新增 `自选股复盘` 页面和通知配置区域。自选股管理页面只管理股票池，复盘页面只看结果。

## 成功标准

- 用户可以维护一个长期自选股池，而不是反复导入临时列表。
- 系统每天自动告诉用户哪些自选股、哪些板块值得复盘。
- 自选股与涨停股、强势板块、资金流之间的关系能被看见。
- 重要风险能被醒目标注。
- 企业微信、飞书、Telegram、邮件至少一个通道可稳定收到每日摘要，其他配置好的通道也能同时发送。
- 历史 AI 观察可以解释“当初为什么关注、后来发生了什么”。
