# 每日报告生成流程

本项目的日常入口是：

```bash
make report DATE=YYYY-MM-DD
```

例如：

```bash
make report DATE=2026-05-27
```

## 生成流程

1. 读取 `apps/api/.env` 和环境变量。
2. 通过 TickFlow 获取市场行情和强势板块。
3. 通过 Anspire 搜索板块相关新闻。
4. 抓取同花顺/东方财富复盘信息。
5. 根据行情强度、复盘确认、前排个股、催化和风险生成次日预测。
6. 生成结构化复盘 DTO。
7. 执行全日盘后质量门禁，写入评分、发布状态和问题列表。
8. 渲染 `report.html`。
9. 导出 `report.png`。
10. 写入 `report_dto.json`、`snapshot.json`、`news_raw.json`、`llm_calls.json`。
11. 写入 SQLite 报告元数据。

## 输出目录

报告默认生成在：

```text
reports/<DATE>/close/vXXX/
```

常见文件：

- `report.html`：最重要的报告产物。
- `report.png`：HTML 截图导出。
- `snapshot.json`：报告、校验、provider 状态的完整快照。
- `report_dto.json`：报告 DTO。
- `news_raw.json`：原始新闻结果。
- `llm_calls.json`：LLM/结构化生成调用记录。

## 质量门禁

质量门禁 v1 只覆盖 `close` 全日盘后日报。`midday` 和 `weekly` 会标记为：

```json
{
  "publish_status": "not_applicable",
  "score": null
}
```

全日盘后日报会产出三类发布状态：

- `publishable`：85-100 分，可发布。
- `degraded`：70-84 分，可发布但有降级提示。
- `blocked`：低于 70 分或存在硬失败，只能作为不可发布草稿。

硬失败包括行情主源失败或 fake fallback、事实校验失败、前二板块缺少前排股、关键 provider 状态缺失、结构化复盘缺失或失败。`blocked` 不会阻止草稿生成，但定时任务不会把它当作“已有可用日报”，下次到点仍可重试生成。

质量门禁会写入：

- `report_dto.json` 的 `quality_gate`。
- `snapshot.json` 的 `quality_gate` 和 `report.quality_gate`。
- SQLite `reports` 表的 `quality_score`、`publish_status`、`quality_summary`、`quality_gate`。
- `report.html` 顶部质量门禁横幅。

## 如何确认报告没有 fake 内容

打开 `snapshot.json`，检查：

```bash
jq '.provider_status.market' reports/<DATE>/close/<VERSION>/snapshot.json
```

正式报告应看到类似：

```json
{
  "provider": "tickflow",
  "status": "success",
  "fallback_used": false,
  "reason": null
}
```

如果 `fallback_used=true`，不建议把该报告当作正式复盘。

## 清理旧版本

保留最新版本，删除同一天旧版本：

```bash
find reports/2026-05-27/close -maxdepth 1 -type d -name 'v*' ! -name 'v003' -exec rm -rf {} +
```

注意：`reports/` 默认不提交到 GitHub。
